# Design Decision Records (ADRs)

These records distinguish **approved choices** from ideas for future discussion. Status names: **Accepted**, **Proposed**, **Superseded**, **Rejected**. A proposal is not an instruction to implement.

## Recording a new decision
1. State context and alternatives.
2. List chosen outcome and consequences.
3. Cite the creator's explicit agreement in the dated journal.
4. Update the affected GDD links and [open questions](../gdd/12-open-questions.md).
5. Never delete a superseded ADR; add a successor and link it.

Do not confuse the design discussion's confident recommendation with explicit creator approval.
